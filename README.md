# Québec French — audio pack

Pronunciation recordings for the **Québec French** app, published here as release assets so
the app can download them on demand instead of shipping them inside the APK.

Every release is one zip plus a JSON manifest. The repository also serves
`https://french.doctornova.net/` from `site/`, and that is where the **web** app gets its
audio — see below.

> ⚠️ **This repository keeps exactly one commit.** `site/audio/` is half a gigabyte of
> binary that git cannot delta, so keeping history would add another ~511 MB every time the
> corpus is re-synthesized. Record work with `pnpm git:squash`, which folds everything into
> a single commit and force-pushes. The script explains itself.

## What is in a release

```
quebec-french-audio-vN.zip
  manifest.json          what each recording says, and which file holds it
  audio/<xx>/<hash>.opus
```

Clips are keyed by **the spoken text**, never by a database id, so the pack stays usable
without the app, its schema, or its source. Unzip it anywhere, read one JSON file, and
every recording is addressable.

## Why the packs are published twice

The Android app downloads `audio-<voice>.bin` straight from the release above. The **web**
app cannot: GitHub serves release assets with **no `Access-Control-Allow-Origin` header**,
on the redirect and on the final response alike, so a browser refuses the request before a
single byte arrives. A plain download link would work — navigation is not subject to CORS —
but the file would land in the user's Downloads folder, where a web page can never read it.

So the same bytes are published a second way, under `site/audio/`, which GitHub Pages serves
with `access-control-allow-origin: *` and honours range requests on:

```
site/audio/
  audio-zoe.bin.000 … .003      <=90 MB each, because git rejects files over 100 MB
  audio-zoe.bin.parts.json      the order and sizes; the web app reads this first
  audio-denis.bin.000 … .002
  audio-denis.bin.parts.json
```

The pieces are a transport detail. The web app stitches them back into one file in the
browser's private filesystem (OPFS), byte-identical to the phone's, and reads clips out of
it by the same byte offsets. Produce them with `pnpm split:pack --voice <id>` in the app
repo; the app's own `doc/architecture.md` §13.18 has the reasoning.

**Two limits.** A published Pages site may not exceed **1 GB** — this is about half — and
Pages bandwidth is soft-capped at **100 GB/month**, which is roughly 370 full pack
downloads. Playing individual clips is ~8 KB each and does not matter.

## The voices are synthetic

All audio is generated by text-to-speech, not recorded by human speakers. It is intended
as a pronunciation reference for learners of Québec French, and it is not a recording of
any real person.
